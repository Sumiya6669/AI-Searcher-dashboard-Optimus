# AI MultiSystem Dashboard

Операционный интерфейс к работающей системе мониторинга отрасли, конкурентов и
государственных закупок. Отвечает на один вопрос: **нужно ли что-то делать
прямо сейчас**.

Это не отчётность и не набор графиков. Данные система уже собирает — сценарии
n8n пишут их в Supabase; дашборд показывает то, что собрано, и состояние самого
сбора, потому что раздел без данных выглядит спокойным точно так же, как раздел,
в котором ничего не происходит.

## Стек

| | |
|---|---|
| Каркас | Next.js 15.5, App Router, React 19, TypeScript strict |
| Оформление | Tailwind CSS 4, собственные компоненты, `lucide-react` |
| Данные | Supabase PostgreSQL, чтение только на сервере от имени пользователя |
| Развёртывание | Vercel |

Внешних библиотек графиков нет: единственный график — расход на модель по суткам
— нарисован разметкой SVG, и это дешевле, чем тянуть библиотеку ради одного
блока.

## Запуск

```bash
npm install
cp .env.example .env.local     # заполнить NEXT_PUBLIC_SUPABASE_ANON_KEY
npm run dev                    # http://localhost:3000
```

Демонстрационный режим — без базы и без входа:

```bash
DASHBOARD_DEMO=1 npm run dev
```

Проверки:

```bash
npm run typecheck              # tsc --noEmit
npm run build                  # production build
node smoke.mjs                 # 29 маршрутов против собранного приложения
node overflow.mjs              # переполнение по горизонтали на трёх ширинах
```

## Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | да | адрес проекта Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | да | публикуемый ключ; попадает в браузер по назначению |
| `NEXT_PUBLIC_SITE_URL` | да | базовый адрес для ссылок в письмах сброса пароля |
| `NEXT_PUBLIC_N8N_BASE_URL` | нет | только для ссылок на выполнения сценариев и форму получателей |
| `DASHBOARD_DEMO` | нет | `1` — данные из изолированного набора, запросов к базе нет |

**Сервисный ключ Supabase здесь не используется и не должен быть задан.**
Токен n8n, токен бота Telegram, ключи Brave, Google, VK, Perplexity в
приложение не передаются: они нужны сценариям сбора, а не интерфейсу.

## Развёртывание на Vercel

1. Создать репозиторий и залить эту папку:

   ```bash
   git init
   git add .
   git commit -m "AI MultiSystem Dashboard"
   git branch -M main
   git remote add origin git@github.com:<аккаунт>/ai-multisystem-dashboard.git
   git push -u origin main
   ```

2. На vercel.com → Add New → Project → импортировать репозиторий. Framework
   определится как Next.js, настройки сборки менять не нужно.

3. В Settings → Environment Variables добавить для Production и Preview:

   ```
   NEXT_PUBLIC_SUPABASE_URL      = https://ajmwzzahcdtkikzhxzqu.supabase.co
   NEXT_PUBLIC_SUPABASE_ANON_KEY = <публикуемый ключ из Supabase → API>
   NEXT_PUBLIC_SITE_URL          = https://<имя-проекта>.vercel.app
   NEXT_PUBLIC_N8N_BASE_URL      = https://optimusalbertgaan.app.n8n.cloud
   ```

   `DASHBOARD_DEMO` в production не задавать.

4. Deploy.

5. В Supabase → Authentication → URL Configuration добавить адрес Vercel:
   Site URL — `https://<имя-проекта>.vercel.app`, Redirect URLs —
   `https://<имя-проекта>.vercel.app/auth/callback`. Без этого ссылка из письма
   для смены пароля будет отклонена.

6. Завести первого пользователя: Supabase → Authentication → Users → Add user
   с подтверждённым адресом. Он автоматически получает роль администратора.

Регион Vercel лучше выбрать европейский (`fra1`): база находится в
`eu-central-1`, и каждый лишний океан между ними — это задержка на каждый
запрос страницы.

## Устройство

```
src/
  app/
    (auth)/            вход, восстановление и смена пароля
    (app)/             приложение: общая оболочка и все разделы
    api/search/        глобальный поиск (серверный маршрут)
    auth/callback/     обмен кода из письма на сессию
  components/
    layout/            оболочка, боковое меню, заголовок, поиск, уведомления, тема
    ui/                карточки, таблицы, значки, кнопки, состояния
    domain/            лента событий, показатели, значки предметной области, график расхода
  server/
    supabase/          клиенты для сервера и браузера
    auth.ts            профиль и роль текущего пользователя
    queries/           слой данных: по одному модулю на раздел
    demo/              изолированный демонстрационный набор
  lib/
    domain.ts          правила предметной области: важность, срочность, свежесть
    format.ts          даты, суммы, числа, часовой пояс
    types.ts           типы строк базы
    url.ts             состояние фильтров в адресе страницы
```

Правила, которых стоит держаться при доработке:

- **SQL и бизнес-логика не живут в компонентах.** Компонент получает готовую
  строку и решает, как её показать. Отбор, сортировка и постраничный вывод
  выполняются в базе.
- **Пороги не зашиваются в код.** Порог значимости лота, порог уведомлений,
  число падений подряд до тревоги приходят из настроек базы через
  `app_thresholds()`. Шкала важности и правила срочности описаны один раз в
  `lib/domain.ts`.
- **Ошибка одного блока — ошибка этого блока.** Каждый запрос возвращает
  `Result<T>`, и блок отображает свою ошибку сам. Страница из пяти показателей
  не падает целиком из-за одного недоступного запроса.
- **Состояние фильтров — в адресе.** Ссылку с готовым отбором можно переслать,
  и кнопка «назад» работает без отдельного кода.

## Что показывает

| Раздел | Отвечает на вопрос |
|---|---|
| Дашборд | нужно ли что-то делать прямо сейчас |
| События | что произошло, насколько важно, кого касается, почему попало в систему |
| Конкуренты | кто из конкурентов активизировался и не сломался ли обход |
| Бренды и направления | по каким брендам рынок говорит и доходит ли это до человека |
| Госзакупки | какие лоты закрываются первыми |
| Источники | откуда берётся материал и где охват просел |
| Система | запуски, отказы, расход на модель, доставка, резервная копия |

Три правила отображения, которые легко нарушить при доработке и которые стоят
за половиной пользы интерфейса:

1. **События сортируются по важности, затем по свежести.** Сортировка только по
   дате прячет критичное событие вчерашнего дня под фоновой новостью
   сегодняшнего.
2. **Нули не скрываются.** Бренд с нулём событий, неподключённый источник,
   конкурент без изменений остаются в списке. Ноль может означать и молчание
   рынка, и то, что данные не пришли, — различить это можно, только увидев ноль.
3. **Цвет срочности лота означает время, а не деньги.** По деньгам решает
   человек, по времени решает календарь.

## Почему переменные окружения лежат в репозитории

`.env.production` закоммичен намеренно. В нём только значения с префиксом
`NEXT_PUBLIC_`, то есть те, что по назначению попадают в браузер: без адреса
проекта и публикуемого ключа Supabase не работает даже форма входа.

Ключ безопасен не потому, что его прячут, а потому, что у роли `anon` в схеме
`public` нет ни одного права, а вошедший пользователь видит данные только после
того, как администратор выдал ему доступ (`app_users.is_active`). Проверяется
это в базе, а не в коде приложения.

Если предпочтительнее держать значения вне репозитория — перенесите их в
Vercel → Settings → Environment Variables и удалите файл: приложение читает
переменные окружения, а не файл.

## Требования к версии Next.js

Не опускайте версию ниже 15.2.3. В более ранних есть обход middleware через
заголовок `x-middleware-subrequest`, а middleware здесь — первый рубеж
проверки входа. Vercel такие версии к развёртыванию не допускает и правильно
делает. Второй и третий рубеж — серверная проверка в разделе и политики RLS —
остаются на месте, но полагаться на них одних не следует.

## Известные ограничения

- Страница «запись не найдена» отдаётся с кодом 200, а не 404: оболочка раздела
  уже отправлена браузеру к моменту, когда становится известно, что записи нет.
  Содержимое при этом правильное. Лечится вынесением загрузки уведомлений из
  общей оболочки в отдельную границу Suspense.
- Обновление данных — по кнопке и при переходе между разделами. Живого
  обновления через подписку Supabase Realtime нет: при частоте сбора раз в
  15 минут и раз в 3 часа оно ничего не добавляет, а соединение держит.
- Раздел «Настройки» показывает подписки, но не меняет их: подписки
  настраиваются формой в n8n, где заводится получатель и берётся его
  идентификатор чата. Вторая точка редактирования означала бы две расходящиеся
  настройки.
- Вакансии конкурентов в интерфейсе отсутствуют, потому что их нет в данных:
  рабочего раздела вакансий не нашлось ни у одного из наблюдаемых сайтов.
